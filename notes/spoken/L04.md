[A student asks whether checking the boundary conditions first is wasteful, since most data is normal.] The point of checking the boundary conditions first is that you are then always sure your data is not invalid. ## 3. A Boolean condition selects a control-flow path
Status: taught

This lecture is about `if`: turning requirements into safe, testable branches. Branches here mean that when you write a program with an `if` condition, if something is true you do one part of the program, and if the condition is false you do another part - so your program has split into two branches. If the condition is true you are doing only this part of the program; if it is false, only that part. That is what branching means.

We can do branching in C++ in several ways, and one of the common ways is the if-else statement. You check whether a particular condition is true or false, and based on the outcome we decide which part of the code to enter. For example: if you have not submitted the assignment, then one part of the code sends you to submit it; else, if you have already submitted it, I go to the part of the code where I evaluate whether you have submitted a correct assignment or not. That is an example of branching.

You can have several branches, and when you have several branches, how you order them is very important. What you want to do is exhaustively work out all the possible cases, and then build your branches from that. The way to do it is to find the boundary conditions first: you don't want the generic cases first, you want the exceptional cases first.

For example, if you are branching on a variable called temperature, in Celsius: if the temperature is less than 0, that is one case; if it is between 0 and 100, another case; if it is greater than 100, another case. Three different cases. Now, we want the conditions for less than 0 and greater than 100 first, because those are the boundary conditions, and we want the working range to be between 0 and 100. Every time you write your code, remember that you want to handle the boundary conditions first, because we want the input to be valid. First you handle the boundary conditions; whatever remains is the normal condition, and then you go into the normal condition and work out what to do next.

## 8. switch selects among cases for one discrete value
Status: taught

The same thing we did already can also be done another way. Instead of writing `if`, `else if`, `else if`, `else`, you can write a branching condition another way, and that is the switch-case.

In a switch you put the variable you want to switch on. Think of a switch-case like a light switch: there are two states for a light switch - on and off. If I leave the switch hanging in the middle, what is the state - on or off? [A student: Schrodinger's switch.] No, it is not, because this is a deterministic system, not a quantum system. If I leave the switch hanging, it is not actually on. When the switch is on, it is on: the current has to flow. It is not that sometimes the current flows and sometimes it doesn't. So the switch has only two states.

When we switch on a variable that has only so many different values, you can have a different case for each value. Here we are looking at `menuChoice`: if the value of `menuChoice` is 1, it will do this line. And then you need to write `break` after the statements of a case. `break` means it will jump to the end of the switch. If you do not put `break`, execution just carries on into the next case's statements. With if-else-if, once one of the conditions is true it goes directly to the end; but in a switch, if I remove the `break` here, it does `case 1` and then keeps going and also prints `case 2`. {+The switch jumps once, to the label that matches, and from there it runs the statements in order until it meets a `break` or the end of the switch; the labels it passes on the way are not tested again.+}

A switch is in some sense like a drop-down menu: you have a bunch of options and you want to choose one of them. Here, for `menuChoice`, you have two options, 1 and 2, and the third one is `default` - the case where you did not choose one of the given values.

[A student asks whether a switch can have an undetermined number of cases, say n.] No. A switch-case is a deterministic thing, so the number of cases is fixed by how many you write in your code; you cannot dynamically generate the number of cases. If you write five cases, there are only five cases - there is no sixth case.

[A student asks whether you can use a plus or minus sign in a case.] In a case you are comparing exactly: you write `switch (x)`, and `case a` means that if `x` equals `a` it will go there automatically. You cannot do operations there.

## 9. Check yourself: what can a switch select on?
Status: taught

The question is: which one of these cannot control a switch statement? What do we mean by the question? When you are doing a switch-case, what you want is finitely many values. If the data type can take finitely many values, then you can do a switch statement on it. So which one of these does not take finitely many values? [Students: `double`.]

The answer is `double`. An enumeration value - there is a data type called `enum`, where you give, say, four different options, and each of these options has a value like 0, 1, 2, 3, so an `enum` of size four gives you four options, in the same way that a boolean is just two options. So an `enum` has finitely many values.

With an integer, for example, you can compare exactly; with a `double` you cannot compare exactly. A `double` is also finitely many in a sense, because we are working with a computer and a double has a bit-size limit. But the problem is that comparing two double values for equality is not reliable: if you define the fraction as 1/3 and store it in a double, versus defining it as (1/9)*3 and storing it in a double, you may get different values. {+The same expression gives the same answer every time; the trouble is that two expressions that are equal in mathematics can round to different doubles.+} That is where comparing doubles is not useful. I would say: don't compare doubles. Even in `if` statements, don't compare doubles for equality. A switch-case is comparing for exactly equal values. If you want to compare doubles you use greater-than-or-equal, less-than-or-equal, greater-than or less-than - those are fine, more or less. What you don't want is exact equality, `==`.

So a `double` cannot be used, because a switch-case compares discrete values and a double is continuous in some sense. And don't get confused by the fact that one option is written in blue - it is blue because it is a new term.

## 15. Boundary tests reveal wrong comparisons early
Status: taught

What we want is safe branching. Every time we use if-else statements or switch statements, we want to first verify which branching is safe, and then go from there. So whenever you write a program, the first thing you should do is work out which branches you need: you write down a table. If this value is greater than zero I will do this; if this value is less than zero I will do that. Then - what did I miss? If I say `a` is greater than zero I do this, and if `a` is less than zero I do that - what did I miss? [Students: Equal to zero.]

So whenever you are branching on something - you take a variable x and you want to branch on some boundary parameter y - you must consider x greater than y, x less than y, and x equal to y. All three cases. If you do not consider all three cases, you are missing something.

That is how you translate a decision into a branch when you are writing the code.
