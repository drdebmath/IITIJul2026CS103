## 1. while, do-while, progress, and stopping
Status: taught

Last time we learned about conditions and branching. What is branching? When you have a condition which is either true or false, you can put branches on that condition: if it is true you do some part of the code, and if it is false you do some other part. That is how you write an if statement, an if-else, a switch, and so on.

Today, suppose there is a part of the code that you want to do many times, but you don't want to write the condition in the code many times - "I have to check this condition again and again, and as long as it is true I have to do it." Then you write a loop.

There are two ways we will learn: one is called a while loop, and the other is a do-while. There are subtle differences, and we will learn those as well.

What a loop actually does is maintain the state of the condition: if the state of the condition is true you do something, and if it is false you don't. And you also have to have termination: when you run some code many times, you want the code to eventually stop. If it does not stop, then you are stuck in the loop - like running in the same place, not going anywhere. If your condition is trivially true in all cases, you can never get out of the loop; the program will never end and the computer will never stop running. That is not what we want when we write code: we want the program to do something and eventually stop.

## 2. while repeats while a condition stays true. · Production-line quality scan
Status: taught

Suppose you become a manager at a supply-chain factory, manufacturing solar panels, and you have to check whether each solar panel is completely flat or whether there are aberrations on it. There is a camera that scans the panel and tells you its size and the angle of the panel. If the angle is more than 0.05 degrees, you discard it, because it is a defective panel. But you have to do that repeatedly.

So the loop processes repeated measurements, counts defects, and stops early if there are too many failures. That is broadly what a loop is, and now we will see the syntax.

Coming back to the production-line example: you have some samples, and you already know how many samples you have, because you take that as input. If you look at line 5, we read `samples`. Then we want to run a while loop.

Whenever you run a loop, there are three parts: the initialisation, the condition, and the termination. `int i = 0` is the initialiser. What we are doing with this loop is counting the samples: as the samples go through, we count them one by one and check something about each sample - whether it is good or bad. That is the objective of this code.

So first we do the initialisation, `i = 0`, and then the condition is `i < samples`. Just as in an if statement we write the condition inside parentheses, for a while loop we write `while`, and then the condition in parentheses. Then, inside the curly braces of the while loop, whatever is there runs while the condition is true; when the condition is false, it stops. The condition is true at the start, because `i` is 0 and `samples` is something greater than 0. If `i` is 0 and `samples` is 10, is the condition true? Yes.

Once the condition is true, this part of the code gets executed. What is happening there? We take the diameter of a sample - suppose you are manufacturing cricket balls. If the diameter is less than 9.95 or greater than 10.05, we say the ball is defective, because it is not the proper size. Then we write `++defects`, and `defects` was also set to 0 initially. So initially there were no defects, and every time this condition is true - the diameter is less than 9.95 OR the diameter is greater than 10.05, joined by an OR, so either one makes the whole thing true - we add 1 to `defects`. The `++` is the increment operator we have learned. [A student asks whether `defects += 1` is the same as `defects++`.] Yes, `defects += 1` and `defects++` do the same thing here.

We are building on top of each other: this code already uses everything you have learned in the first four lectures. [A student asks about the `++`.] You can use it either on the left side or on the right side. {+`++i` gives the new value, `i++` gives the old value and then increments; on a line by itself either form just adds one.+}

[A student asks whether `++defects` and `break` should be inside curly braces.] No, they are different statements. This is one more tricky thing about if statements: if you don't put curly braces, the `if` only covers up to the semicolon, so this `if` ends at the semicolon. If you put curly braces you can have multiple lines; if you don't, you can only have exactly one statement after the `if`. That is why this `++defects` ends here, and this `if` ends here. You have to test these things yourself.

[A student asks about the defect count.] As soon as the number of defects reaches 3, it breaks out of the loop. So the final value of `defects` could be 0, 1, 2 or 3, and it cannot be more than 3, because every time it reaches 3 we stop and don't check the remaining samples. But if there are no defects - suppose you have 10 samples and fewer than 3 defects - then all the samples must be checked. So if the defects appear early, you stop early; if the number of defects stays small, you go through all the samples.

How do we know that the while loop will terminate? The condition is `i < samples`. Every time the code reaches line 14 it goes back to line 8 and checks whether `i` is less than `samples`. And on line 13 we have `++i`. Initially `i` was 0 - as I said, we need an initialiser for every loop.

[A student asks whether it should be `i <= samples`.] We start at 0, so if you have 10 samples, `i` goes from 0 to 9.

Because we increment `i` on line 13, every time the loop runs the value of `i` increases by 1, so the loop can only run as many times as there are samples; it cannot run forever. That is what I mean by "the loop must progress towards termination". Termination here is the end of the loop, and the loop ends when the condition becomes false - which happens when `i` becomes equal to `samples`.

[A student asks whether you can use more than one logical operator.] Yes, you can always keep these statements joined by several operators.

So this is what the code does. You take some number of samples; then for every sample it takes a diameter; it checks whether the diameter is in the acceptable range or not; if it is out of range it increases the number of defects; and once the defects reach 3 it breaks out of the loop and reports how many defects were found. If the defects never reach 3 - all the samples are more or less good - then the while loop stops when the condition becomes false, which happens when `i` reaches `samples`.

The takeaways: `while` repeats while the condition is true. The state of the loop is the set of values compared in the condition - here `i` and `samples` - and `i` increases gradually, so the state of the loop moves towards termination. And `break` is appropriate when what we want from the process is already known: what we want is whether the samples have too many defects, so as soon as we find 3 defects, we stop. We don't need to keep running the loop. What do you use to get out of the loop? [Students: `break`.]

## 3. The general form of a while and a do-while
Status: taught

How do we write a while loop? We have the keyword `while`, and then in parentheses we write the condition. The condition could be anything, and it is inspected every time the loop runs. While the condition stays true this loop will run, and once the condition becomes false it comes out of the loop.

Like the while loop, there is also the do-while loop. In a do-while you write `do`, then the body in curly braces, and then you put the `while` at the end with the condition in parentheses - and after the `while` condition you need a semicolon. The semicolon is where the do-while statement ends. If you don't put the semicolon you will get a compilation error {+- the compiler rejects the code, so the program does not run at all+}.

So these are the two ways to write a loop: `while (condition)` and then curly braces with whatever runs in the loop, which keeps running as long as the condition is true {+- zero times if the condition is false at the start, and forever only if nothing inside ever makes the condition false+}; or `do`, then curly braces with what runs in the loop, and at the end of the closing brace `while (condition);` finished with a semicolon.

What is the difference between a while loop and a do-while? A do-while runs its body at least once, without checking the condition first. In a while loop, first you check the condition, and if it is true you go inside the loop. In a do-while, first you go inside the braces and execute everything, and then at the end you check whether the condition is true or false. So in a do-while everything gets executed at least once, whereas in a while loop it only gets executed if the condition is true. So in a do-while the initialisation of the condition does not matter in the same way: you can leave the condition's value unknown until after the first pass, because the body will fill it in before it is tested. {+The condition still has to be a valid expression, and every variable the body itself reads - a counter, a total - still needs a sensible starting value; only the check is postponed, not the setup.+}

If you could explain a while loop in one sentence, what would you say? [A student: The condition is checked every time the loop runs.] Yes: the loop runs while the condition is true, and stops once it is false.

How is the do-while loop related to the while loop? [A student: If the while loop fails the condition it does not run at all, but the do-while must run once.] Yes. So basically, in a do-while the do part of the code gets executed regardless of the condition.

## 4. Trace the condition and update to predict every while iteration
Status: taught

Now we will do something called tracing the loop, which is important. Whenever you write code you have to trace the state of the variables, one by one, for every iteration of the loop. If you don't, you cannot see when the condition becomes false.

Look at this code. We start with a variable `remaining`, set to 3. Then the while condition is `remaining > 0`, and while `remaining` is greater than 0, whatever is inside the curly braces gets executed.

Inside the braces there is `--remaining`. So every time the loop runs, what happens? `remaining` decreases by 1. And what else is inside the loop? It prints the value of `remaining`. So what will it print? [A student: 3, 2, 1, 0?] It will not print 0. Why not? Because the condition is `remaining > 0`: when `remaining` becomes 0, the condition is false, so it does not go inside the loop and does not execute the print. So the output is 3, 2, 1 - "3 space 2 space 1".

## 5. Every loop update must move toward termination
Status: taught

When you design a loop you always have to ask yourself what the state of the condition is. If you know exactly what the state of the condition is, you can work out when the loop will end. Then you also work out what must remain true for the loop to run.

It need not be only one condition in the loop - there could be multiple conditions and multiple `break` statements. All of these together are the state of the loop. When you have several conditions and one of them becomes false, that is the end of the loop.

## 6. Check yourself: does this loop make progress?
Status: taught

Can you tell me what this loop is doing? There is a new word in this program - what is it? [Students: `continue`.] What does `continue` do? When you write `break`, it breaks out of the loop; when you write `continue`, it stays inside the loop but skips the rest of this iteration: it does not execute whatever is written after the `continue`, and goes to the next iteration. {+In a `while` loop "the next iteration" starts at the condition test, so an update written after the `continue` is skipped - that is exactly what happens here with `++i`. In a `for` loop it jumps to the update clause first, so the counter would still move.+}

So if `continue` is on line 4, line 5 will not be executed. What happens then? First we start with `i = 0`, and the condition `i < 5` is true, so we print `i` - we print 0. Then the `if (i == 2)` condition is false, so we reach `++i`, and 0 becomes 1. Next round: 1 is less than 5, we print 1, the condition is again false, `++i` makes `i` 2. Next time, 2 is less than 5 is true, it prints 2 - and now the `if` condition is true, so it goes straight back to the top and never reaches line 5. So `i` is still 2, it prints 2 again, the condition is true again, and it loops.

So this is an example of an infinite loop. You should not write code that produces an infinite loop; if you do, your program never finishes and you have to stop it yourself, from the terminal or the IDE. We don't want this kind of infinite loop in our code. {+It will not damage the machine - the program just keeps the processor busy and never produces your output until you kill it.+}

Because of that, when we design loops we always trace the loop state: we keep track of all the variables that are part of the conditions inside the loop, and then we check that the conditions are not conflicting with each other. If they conflict, you get a situation like this one, where two conditions work together to prevent progress towards termination. Your loop should always make progress towards termination; if it does not, there is a problem.

[A student asks about the missing curly braces after the `if`.] There are no curly braces in that `if` statement, because without braces it only takes the next single statement, up to the semicolon.

The answer is this one, because `continue` jumps straight back and then the loop never stops.

## 8. A sentinel lets a loop process an unknown number of inputs
Status: taught

Here we have something called a sentinel, which is used when you don't know how many inputs there are, but you want some condition on the input to stop the loop. It is a loop that runs until the user gives you a particular input. "User" here means the person using your program: you are the programmer, you write the program and deploy the software, and then someone runs it and gives input. Because that person is giving the input, we depend on them for the loop to end.

In a sentinel loop we first take one input from the user, and then we check whether that input satisfies some condition. Here we check whether the value is not equal to -1, and if it is not, we add it to the total. `total` is initially 0.

Suppose you made a calculator app and you want the user to input what they want to add. Or you make a spreadsheet app and you want a list of numbers to total. What you ask the user is to give you all the numbers one by one, and you also give the instruction that once they input the value -1, it will stop.

So -1 is the sentinel here, and `value` is the variable that holds each input: once the user enters -1 the condition becomes false and the loop stops. {+The sentinel has to be a value that can never be real data, and it is not added to the total.+} Until then, whatever else the user inputs - -2, -5, one million, ten million - the loop keeps running. And you can see that inside the loop we take another input: the user enters something and presses enter, and then needs to enter another input, and another, and that goes on until they enter -1.

If we want to do this as a do-while loop it would be easier, because then you don't need the input before the loop: you can put it inside the loop. If you write this as a do-while, line 3 is not required - you just write the body, and then you put `value != -1` in the while at the end. But then you would add -1 to the total, so once the loop terminates you have to correct the total by adding 1 back, because you added -1 to it. That is how you convert a while loop into a do-while loop.

## 11. Check yourself: which loop fits this stopping rule?
Status: taught

A program must read a number and keep re-asking until the user finally enters a positive number. Which loop is the best way to do it: `while`, `do-while`, either, or something else? [A student: A for loop.]

Why is a for loop the wrong choice here? Because you don't know the number of inputs: you have to keep going until the user enters a positive number, and a for loop is for the case where you count. {+You could force it into a `for` by leaving the clauses empty and breaking out, but that hides the stopping rule; the loop that states the intent is the one to use.+} First you need to take some input from the user, and we just saw that the first part of the loop must execute at least once to take that input. If you write a while loop, you have to take the input separately outside the while loop, which is not ideal - and that is why you should use a do-while loop.

[A student says either would work.] You would have to write one extra line of code, but it will work - and that is the difference. Why would you write one extra line? If you are a good programmer you minimise the number of lines: if there is a solution that takes two steps, why would you write five? That is what you did in JEE: if you know the trick to solving the problem, you use it. Did you do integration by parts for the whole thing, when you know one part is zero and everything else is multiplied by it? No - you evaluate that one part to be zero and say zero is the answer. That is the point here: if you know `do-while` can do the job minimally, you use that.

Even without a loop you could write the same statement a thousand times. Do you want to write a statement a thousand times every time you want to check the condition? No. The point of learning different pieces of syntax and how the program works is to use them so that we minimise the total number of steps.

## 14. Stalled updates and wrong bounds break loops
Status: taught

One of the things you need to keep track of is the off-by-one error. What is off-by-one? When you run a loop you are incrementing some value, and that value can get shifted by one. You start at zero, and instead of writing less-than you write less-than-or-equal: then, if you want the loop to run ten times and you start at zero, it will run eleven times. We don't want eleven times, we want ten. So whenever you write less-than or less-than-or-equal in the condition, you should be careful about whether you are accommodating an off-by-one error.

## 15. Stop a scan as soon as the answer is known
Status: taught

We already saw this in the first example. We can also put the defects condition here: in the previous code, whenever `defects` was greater than or equal to 3 we put a `break` statement - but instead of a break inside the body, we can put both stopping reasons into the while condition itself.

Thinking before writing is very important: you want to write a minimal amount of code, so instead of writing one more line to check the defects, put it in the condition. When your code becomes bigger and bigger these things matter. And this is better to read, because we are putting both conditions in the same place: while both of them hold the loop runs, and as soon as either one fails the loop stops - because we want to test until all the available samples are tested, and we want to stop when the number of defects reaches 3.

This is an exercise: you should write a while loop yourself and trace it, and you should do it on pen and paper. If you write the code directly and just run it, you will not notice things. So while you are learning, do the trace on pen and paper and then verify it by running it on the computer, and check whether the output matches what you predicted.

## 17. Choose a loop by its stopping rule and prove its progress
Status: taught

The stopping rule: a while loop can execute zero times, because the condition could be false at the beginning. A do-while executes at least once, because the condition is checked at the end of the loop. A sentinel is the value the user gives you to terminate the loop, so if you don't know how many inputs there are, you use a sentinel.

The state of the loop keeps track of all the variables that are responsible for the loop: the conditions that let you exit the loop, and the variables in them, make up the state.

And when you trace a loop, you always keep track of the normal state, the boundary condition and the invalid case. If the input says you should enter positive numbers, then entering a negative number is invalid.
