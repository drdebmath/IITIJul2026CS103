## 3. A for loop makes initialization, bound, and update explicit
Status: taught

[Continuing the `++` question from the previous class.] Line 15 doesn't change. If I remove the `++`, it should print 0. The `++` moves it to the next value. With `i++` the value used in the expression is the old value of `i`, and `i` is incremented as part of the same expression {+ - as a side effect of that statement, not as a separate statement inserted after the semicolon; by the time the next statement runs, `i` is already the new value +}. When you put the `++` before the variable, the increment happens first and the expression uses the new value.

[A student asks what happens with `++i`.] {+ Here is the exact behaviour. In `x = ++i` the increment happens first and `x` gets the new value. In `x = i++` `x` gets the old value, and `i` is incremented as part of the same expression, not in a separate statement after the semicolon; when the next statement starts, `i` already holds the new value. So a lone `cout << i++` prints the old value and a lone `cout << ++i` prints the new one, and this does not depend on the compiler - every compiler gives the same result for ordinary code like this. The only place where the result is not fixed is an expression that modifies the same variable twice, such as `i = i++ + ++i`; that is undefined, and the answer there is not to write it. +}

The point is that in `x = ++i` the increment happens first and `x` gets the new value, while in `x = i++` `x` gets the old value and `i` is incremented before the next statement. That is why you should be very careful about using several `++` or `--` operators in the same statement. It is good practice to separate them into different statements: if I write it before or after, then it is clear that this has happened and this is done, and it will not create issues.

So here we have one initialiser. A for loop has three things: the initialiser, the condition, and the increment - not necessarily an increment, it could be a decrement; it is the update. This is the initialisation, this is the condition, this is the update: the three parts of the for loop. So instead of a single condition, as in a while loop, the header has three parts.

## 7. Nested loops enumerate every coordinate or combination
Status: taught

You don't have to have only one loop at a time; you can use several loops, and you can put a loop inside a loop.

For example, in the snake game you have a horizontal direction and a vertical direction, and you want to reach each spot of the game. Or take this classroom: there are so many tiles, tiles this way and tiles that way, and you want to give each of these tiles a specific number. How do you do that? You number them this way and that way. I start there: that is zero, this is one, two, three, four - five rows. And then across, 0, 1, 2, 3. So if I give two indices, one for the row and one for the column, I can address all the tiles individually. Can I do that? Yes.

That is why, when you want to address more than one dimension, you need one index per dimension - and for each index you need one for loop. With two dimensions you need two for loops, and then you can reach the positions individually by putting one for loop inside another.

Now, because you are putting two for loops, does it matter which one you put outside and which one inside? How many of you think it matters? How many think it does not? [Students: it depends on the relationship.] No, it always makes a difference. It always matters. {+ Both orders visit the same set of (row, column) pairs, so the cells you reach are the same; what changes is the order in which they are visited and printed, and, as we will see now, the order in which the memory is touched. +}

When you do this you also have to think about the order in which you access the memory in the computer. Memory is not stored randomly; it is stored in a particular order. If you are accessing it row-wise, one by one, then the outer loop goes over the rows and the inner loop walks along the columns of one row - `for (row) { for (col) }`, as in the examples on the slides and in the snake printer. {+ In memory the elements of one row are stored next to each other, so the index that moves fastest, the inner one, should be the column. +} If this tile is memory block one and the next is memory block two, then memory block two is right next to memory block one. Suppose there are ten of these in a row, so the tile below becomes memory block eleven. If you put that loop outside, what happens? You access memory block one, then memory block eleven, then memory block twenty-one - which is slow. If you access them one by one in sequence - one, two, three, four - it is faster.

So you need to be careful about the way your memory blocks are stored, so that you can order the for loops accordingly. If you don't care, you will say: I can put this loop outside or inside, it doesn't matter, I can swap them. If memory access took the same amount of time for every block, it would indeed not matter: you could access memory block one and memory block ninety-nine in the same time. But that is not how computers work; there is a restriction. When the computer brings memory to the CPU, it does not bring one block at a time - it brings, say, eight blocks at a time. So if blocks one to eight are already near the CPU and you access block one and then block nine, the blocks two to eight that were brought in are wasted and another set, nine to sixteen, has to be fetched. We don't want that. {+ This traffic is between the CPU's cache and the main memory; the hard disk is not involved. +} If you want to write efficient programs, you have to be careful about which loop is the inner one and which is the outer one.

Here, when it is very small - say three by four, so twelve data points in total - the whole thing fits in three memory blocks, and the computer is fetching eight at a time, so it does not matter whether you put the row loop outside or inside. But suppose you have one million blocks: then you have to be careful.

It is not necessary that it is always three by four. You could have an enormous snake game of one million rows by one million columns. Is that possible? Can you make one? Do you think your computer can run a one-million-by-one-million snake game? [Students: six hands go up.] How would you run it? Should it render the entire map at once? No - you only render the part you need. That is how you can run a one-million-by-one-million game: you don't need to access all of it at once. You only need to care about where the snake's head is; everything else is outside your view. You check the neighbourhood of the snake's head: if the next cell is empty, the snake can move forward; and if there is food, the snake grows longer, so you update the length of the snake. The length could be arbitrarily large - one billion, ten billion - we don't care. It would be very, very slow, but you can do it.

One million times one million is 10^12 - one trillion. How much data is one trillion bytes? When your hard disk says one terabyte, that is roughly that. So one trillion is not that large for this particular thing. And there is also something called compression: you don't need to store everything as it is. We will not learn about that in this course; I am just giving you an idea of why the choice of how you access memory, and how you order your for loops, matters. When it is a million by a million, you have to be very careful about where you put the for loops.

## 9. A loop invariant states what stays true after each iteration
Status: taught

How is the loop invariant related to the for loop - what is the loop invariant in a for loop?

A loop invariant is a statement about the loop's variables that is true before and after every iteration. {+ It is not the same as the loop condition. The condition is the test that must eventually become false so that the loop stops; the invariant is a claim that stays true after every iteration, for example "sum holds the total of the first i elements", or "step is between 0 and 5". +} For example, we initialise `step = 0` and we check `step < 5`. So `step = 0` satisfies the condition before the loop starts, and after the first iteration `step` becomes 1 and the condition is again true. One invariant here is that the step variable stays within the range 0 to 5 {+ - including the final value 5, where the condition is false and the loop stops; the invariant still holds at that point +}; we are not changing anything else in the loop. Once the condition becomes false, the loop stops.

[A student asks whether the invariant is the condition.] No. The invariant is a statement about the state of the loop - about the variable and what has been done with it so far. What does "invariant" mean in English? It doesn't change. {+ The condition, on the other hand, does change: it is true while the loop keeps executing and becomes false when the loop stops. The variable has to increase so that the condition becomes false at some point, and the invariant stays true at every one of those points, including the last. +}

The loop invariant here is that {+ before the current row is started, every earlier row has already been printed with a dot in every column; +} as long as the condition is true - that this is still part of the grid - it keeps printing dots.

One way to put the invariant is: before iteration i, we can guarantee that iterations 0 to i-1 have already happened. All of you know induction? A loop is, in a sense, induction. When you prove something by induction you say: this is my base case, and it is true; and in the strong form you assume it is true up to k-1 and prove it for k. Here, in the for loop, the invariant is that if you are running the kth iteration, all the iterations before it have already been completed, so for the kth iteration you only need to check the condition for the kth one. You don't need to check all the earlier ones, because writing the code as a for loop guarantees that the invariant has already handled them.

## 11. Choose for, while, or do-while from the stopping rule
Status: taught

You have to know the difference between the three types of loop we have learned: while, do-while and for. You use `while` when you evaluate the condition first; you use `do-while` when you evaluate the condition at the end; and you use `for` when the work is "for each value in this range", so that the start, the bound and the update belong together. {+ The number of iterations may itself be an input, as in `for (int i = 0; i < n; ++i)`; what matters is that the loop counts over a range rather than waiting for an event. +}

Think about what the normal condition for a loop is, what the boundary condition is, and what an invalid input is.
