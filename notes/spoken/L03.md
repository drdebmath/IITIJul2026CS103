## 2. A name is usable only inside its scope
Status: taught

Today we will learn something called scope. What is the scope of a variable? When you define a variable - say you define the variable inside the `main` function, as in the hello world program in the lab - the scope of that variable is local: it is only defined inside that `main` function and nowhere else.

One easy way to think about scope is: whatever curly brace comes before the declaration of the variable, that is its scope. After `int main()` there is a curly brace, and then you declare `int count = 7`; the `count` variable's scope starts at that curly brace and ends where it closes. Every curly brace comes in a pair, and every bracket comes in a pair: if you forget a bracket you get an error, and if you forget a semicolon you get an error.

These braces define the scope of the variable: only inside those braces can you use the variable and access the value assigned to it. Outside the braces, the variable does not exist. For example, if I make a joke inside this classroom, the scope of the joke is the classroom; outside this classroom, if you tell a friend from another batch, they don't know it.

[Walking the code on the slide.] Here I have a variable called `outer`. Where is `outer` valid? Wherever the variable is declared - it is declared on line 4, and the curly brace before line 4 is the one that opens `main`. So this curly brace and its matching one enclose the whole of `main`, and that is `outer`'s scope. The `inner` variable only exists between these two braces, because I put a separate block inside the `main` function, and that limits the scope of `inner`.

So what will it print? It already says 13 in the comment, and it prints 13.

[Running it.] Here it prints 13. But it is printing `outer`. If I print `inner` here, it says "inner was not declared in this scope" - as I just told you, the scope is these two braces, so out here it is not declared. What I can do is move the print statement inside the block, and then it prints 3, because `inner` is set to 3.

[A student asks why `outer` is not 10.] Inside the block we did `outer += inner`, which means we added the value of `inner` to `outer`: `outer += inner` is `outer = outer + inner`. Since `outer`'s scope is the whole of `main` and `inner`'s scope is the inner block, when you use `inner` inside lines 5 to 10 it works; outside lines 5 to 10 it does not. `outer`'s scope is lines 3 to 13, so anywhere between lines 3 and 13 you can do whatever you want with `outer`.

[A student asks what a local scope is for, comparing it with Python.] If you want something to remain local - or you want a temporary variable name that you reuse several times - then every time you define that temporary variable inside a scope, it is not there anywhere else. For example, here is one block; I can write another block, and in it say `inner = 4`, because the first `inner` has expired and I can declare it again. Here `inner` was 3, and there it is 4: the same variable name reused with different scopes.

[A student asks about redeclaring `outer` inside the inner block.] I said it would be an error, but the error did not come, because `outer` got redefined inside the block. Let me trace it: first we declare `outer` to be 10, so if I print `outer` here, the first value is 10. Then I declared `inner` to be 3 and `outer += inner`, so it becomes 13. Then, inside the second block, I declared `inner` to be 4 and a new `outer` to be 5, and `outer += inner` made that one 9. But that `outer` is defined inside the block, so it is gone after the block. When I print `outer` at the end, it prints the outer one, whose value was already changed to 13.

[A student asks how a second `outer` can be defined when the main one exists.] You don't get an error for declaring the same name in an inner block; the inner one hides the outer one until the block ends, and the compiler may or may not warn you. {+This is called shadowing, and `g++ -Wshadow` warns about it. Declaring the same name twice in the same block is the case that is an error.+} But the point of giving names to variables, as I explained in the last class, is that you want to recognise where something is and what it is. If I redefine the variable again and again, the compiler keeps changing which memory the name is associated with. So when this `cout` accesses `outer`, it is accessing this one; when that one accesses `outer`, it is accessing that one. When a name is used in a scope where it is not declared, it finds the one outside.

When you ask for a variable on line 5, the compiler looks for that variable before line 5 - that is how the C++ compiler works. And it always starts with the smallest scope, and then grows bigger and bigger.

[A student asks whether a variable can be declared outside `main`.] Yes, that is called a global variable: you declare it outside the `main` function, and the syntax is the same. I will show you how to do that.

## 4. Scope controls visibility while lifetime controls existence
Status: taught

What does the scope say? It says two different things: the visibility of the variable - where the variable is accessible - and the lifetime of the variable - how long the variable exists while the program is running.

## 5. Storage duration explains when an object is created and destroyed
Status: taught

Scope also controls the storage duration. Whenever you declare a variable and then the scope is over, the memory that variable was using is reclaimed, and it can be used for another variable. {+This happens while the program runs, not at compile time: a local variable is created when its declaration is reached and destroyed when its block ends. That is what the slide calls automatic storage duration.+}

For example, if I say there were two assignments in the lab today, then the total number of lab assignments you have done is `completedExperiments` plus whatever you did today. Here `completedExperiments` is a global variable: it is declared outside `main`, so any function can access it.

Until you have learned about functions, you can use global variables, local variables and smaller scopes to restrict where things are used. Once you learn about functions, functions are a better and safer way to do the same thing. Keeping a variable in the smallest scope that needs it shortens its lifetime, which is how scope helps you manage memory. {+A namespace and a function are for different jobs, not a memory trade-off: a namespace keeps names from clashing, and a function names an operation. A one-line function such as `add1` costs you nothing worth counting; the compiler normally inlines it.+}

## 7. Namespaces keep same-named declarations from colliding
Status: taught

Now we will learn something called the namespace. We learned about scope, and inside a scope a variable is declared. Inside a namespace you can also declare variables, functions, anything - we will learn how to declare functions later.

The point of a namespace is to have your own variables declared inside it. Everyone has their own vocabulary; consider your own life as a namespace. Everyone can define "my name" as a variable, and inside your namespace your name is your name. So everyone can use the same template for the namespace, and you can have different values for the same variables - the variable names don't need to change.

If I am designing a classroom system where I have to store all of your names, roll numbers, CGPA and everything, do I need to declare a separate variable for every one of you? No. What I can do is declare one variable, `name`. When I am using the classroom namespace, `name` means the name of a student; if I use a faculty namespace, `name` means the name of a faculty member; if I use a laboratory namespace, `name` means the name of a piece of equipment. So the same variable inside different namespaces can mean different things, and you can reuse the name - whereas if you use the same variable name inside the same scope, it will give you an error, or it will change the value of the variable.

Or suppose you want to define your own operator. The way I do addition is from the last two digits first, then the second last, then the third last; another way is to do it from left to right. Either way is fine, but I can define the addition function in my namespace to do it one way, and someone else can define it in their namespace to do it the other way, and both are fine. That is the advantage of having namespaces.

We already know that there is a standard namespace. The standard namespace defines `cin` and `cout`; `cout` is the thing used to print. {+They are stream objects, not functions: you write `std::cout << x;`, and `cout("hello")` does not compile.+} The standard namespace is defined like this too: you write the word `namespace`, and then the name of the namespace. Here the name of the namespace is `laboratory`, and inside `laboratory` I want to keep track of how many assignments you have done, so `completed` is an integer. Different namespaces can have the same variable name, and it could even be a different data type.

[A student asks about the Python equivalent.] {+The closest thing in Python is a module: `import math` and then `math.sqrt(2)` is like `std::sqrt(2)`, with the dot doing the job of `::`. Python has no separate namespace keyword.+}

[A student asks whether you can execute something inside a namespace.] In a namespace you can define variables and you can define functions, and a function can run something. When you call a function that is defined inside a namespace, you have to write the namespace before it, with the scope-resolution operator - the namespace defines the scope. Here I am saying that for this `completed` variable I want the compiler to look inside the `laboratory` namespace; that is where the scope-resolution operator comes into the picture. If I write `std::completed` instead, the compiler will search for `completed` inside `std`, and if it cannot find it there, it will give you an error.

[A student asks why the code on the slide is not a complete program.] This is not a complete program; not every code on a slide is a complete program. This one is for expressions and scope.

Typically, namespaces [said as "scope"] are for your information; I don't think you need to use them unless you are working on a big project, or you are part of a big project and want to contribute there. When you have a big project every developer wants their own scope and their own custom definitions. If four of you are working together on one project, you each want to define your own functions and call them from your own namespace. That is one of the reasons for using namespaces.

## 9. Operators combine values into expressions
Status: taught

Then there are things called expressions. Everyone knows what an expression is - you know arithmetic expressions. You have some operations; what are the operations? An expression is any sequence of numbers connected with operations, and the operations could be plus, minus, division, exponentiation, and so on.

Everyone has learned the BODMAS rule. A C++ program has something similar: it has to follow a certain order to evaluate an expression.

For example, if I ask all of you to add 17 and 23, how do you do it? Let me give you three ways and you tell me which one you did. When I add 17 plus 23, I add 17 plus 20, which is 37, and then I add 3 and it becomes 40. How many of you did it like this? [Students: one hand.] Another way: add 7 plus 3 to get 10, then 10 plus 20 is 30, then 30 plus 10 is 40. How many of you did it like this? [Students: quite a few hands.] Or you can do 17 plus 3 to get 20, and 20 plus 20 is 40. [A student: I did 70 plus 20 directly.] If I ask you to do 576 plus 244, you also do it directly - 820. But if I give you ten-digit numbers, can you still do it directly?

So when we evaluate expressions there is a precedence among the operations, and the compiler always evaluates in that order instead of evaluating randomly; that order is the order of precedence.

For example, here `total` is 5 plus 3 times 2. The order of precedence says you do the multiplication first, so 3 times 2 is 6, plus 5 is 11. But if we use parentheses, the parentheses take precedence, so 5 plus 3 is 8, times 2 is 16.

Star means multiplication - everyone knew that. What else does a star mean, apart from multiplication? [A student: Power.] In Python two stars is power, but C++ has no power operator: {+`2**n` does not compile. For a power you use `std::pow(2, n)` from `<cmath>`, or multiply in a loop. The other meaning of `*` in C++ is dereferencing a pointer, which comes later in the course.+}

Then here there is `bool safe = total < 20 && grouped > 0`. This symbol is called ampersand. What is this expression doing? We are evaluating a boolean expression. Whenever you write an equals sign, an expression gets evaluated. Whenever you write less-than or greater-than, another expression gets evaluated, and that expression is called a boolean expression, which tells us whether something is true or false. Here it says `total < 20`. Is it true? `total` is 11, and 11 is less than 20, so it is true; `total < 20` returns true.

Then there is AND. How many of you know truth tables? Everyone - you should. The two ampersands mean logical AND. What does logical AND mean? True and true is true. True and false is false. False and false is false. So here, `total < 20` is true, `grouped > 0` is true, and true and true is true, so `safe` becomes true. That is how the expression is evaluated. When you don't have brackets, the compiler first applies precedence {+- the comparisons bind tighter than `&&`, and `&&` binds tighter than `||`, just as `*` binds tighter than `+` in `5 + 3 * 2` -+} and then, among operators of the same level, `&&` and `||` are evaluated left to right.

If instead of AND it was OR - how do you write OR in C++? [A student: Pipes.] We put two pipes. Now we have this value OR that value. We already know that if the first one is true, the result is true. So if you have already evaluated the first expression to be true, do you need to evaluate the second? No - because regardless of whether the second is true or false, the output will be true. The compiler only needs to know whether the whole thing is true or false; it does not care to evaluate everything. It evaluates from left to right, sees the first one is true, and stops. That is careless of the compiler, but good for us, because it consumes fewer CPU cycles.

We learned about operators last time. How many typical arithmetic operators are there? Plus, minus, multiply, divide. And when you divide two integers, what happens? The output is an integer, because you are dividing two integers. If you write `7 / 2`, the value is 3 instead of 3.5, whatever variable you store it in; {+so `double x = 7 / 2;` holds 3.0.+} If you write `7 / 2.0` or `7.0 / 2` instead, one operand is a double, and the division is done in floating point, so you get 3.5. If you write only 7 and 2, it takes both as integers, and integers give you only integers, so the output is 3. Here 3 is the quotient of the division. And how do you get the remainder? The modulo operator - the percent sign. So 7 % 2 gives 1.

What will you get if you compute 2^n - 1 modulo 3? [Students answer 0.] How many of you think it is 0? Take n = 5: 2^5 is 32, minus 1 is 31, and 31 modulo 3 is 1. So what values of n do you have to choose so that 2^n - 1 is divisible by 3? You have to give a general solution, not a particular one. [A student: Even n.] {+Why: 2 is -1 modulo 3, so 2^n is (-1)^n modulo 3, which is 1 exactly when n is even. So 2^n - 1 is divisible by 3 exactly when n is even.+}

Can you write a program to do that? How would writing a program help here? [A student explains checking the remainder.] What you need is a branching condition: you want to check whether this thing is divisible by 3 or not. How do you write a branching condition? [Students: `if`.] That is what we will learn on the next deck.

Operator precedence is the order in which the operators are evaluated. These are the operators available in C++: arithmetic, relational, logical, assignment and increment operators. Among the logical operators we have AND, OR, and the third one - NOT, which is the exclamation mark. And `!=` means "not equal to". Then there are less-than, less-than-or-equal, greater-than, greater-than-or-equal, and comparison equality: when you are comparing two numbers, a equals b, you use the double equals.

We saw this example earlier, where there is an AND in the middle, because we want to check whether both conditions are true. There is a relational operator on each side, and the relational operators output true or false; then the logical operator joins them to say whether the whole expression is true or false.

Then `+=`, `-=`, `*=`, `/=`. What do they mean? If I write `a += b`, that just means `a = a + b`; it is a shorthand. And there is the increment operator: if I write `a++`, what happens? `a = a + 1`. There is also a difference between putting `++` before the variable and after the variable: find out what changes between `++a` and `a++`.

## 13. Game evolution: One transition updates the world
Status: glanced

This is from the snake game again. If you want to compute the next row and the next column, you can do it inside a small scope instead of a large one, because you want the next row and next column to be specific to that particular moment. You don't want the next row to be a global thing, or a bigger thing inside `main`; you only want to work out where the snake would be next.

Because the game is running, in one iteration it moves one step, so when you compute the next step you compute it inside this smaller scope. The small scope is used for calculating one candidate move. You go left, right, up or down - although you cannot go in all four directions in the snake game, only three. Why? Because one direction is the snake itself: you cannot go back into your own body. And if you want to check whether the move is valid or not, you can do that inside the scope too.
