## 3. std::string syntax
Status: taught

Now let's look at the syntax. How do we declare a string? You include the header, `#include <string>` - that has to be there. Then you declare a string variable with `std::string` and give it a variable name: roll number, email, anything. And you can also initialise the string by writing something inside double quotes.

How do you initialise a character? With single quotes: `char c = 'A'` gives you the character A. When you declare a string, you use double quotes. So if you write a single character in double quotes, it is counted as a string; if you write it in single quotes, it is counted as a character. There is a difference. {+ `'A'` is a `char` and stays a `char`; a `std::string` is initialised from a string literal in double quotes, from another string, or from a count and a character. +}

Then, say you want to make a string that is the letter A ten times. How do you do that? You give the count and the character, and it initialises the string with every character as `a` - it makes `count` copies of that single character.

These are some of the syntactical things you need to keep in mind. In a string, too, the index starts from 0 - every index in C++ starts from 0. Don't forget. Then `substr` takes the position and the length. If you ask for the substring from position 5 with length 3 of the word "position": counting 0, 1, 2, 3, 4, index 4 is `t`, so index 5 is `i` and three characters from there give `ion`. So `substr(5, 3)` returns `ion`, and it is `substr(4, 3)` that returns `tio`. {+ Count carefully here: being one position off is exactly the off-by-one this slide is warning about. +} I will show you examples next.

And the square bracket versus `at` is the same as with vectors: with the square bracket you just access some memory; `at` checks whether the index is within the bounds. And `getline` will get you the entire line - that will be the same.

## 9. std::string owns, sizes, and edits its character sequence
Status: taught

You learned about vectors in the last lecture, so you can think of a string as behaving like a vector of characters. In C you would have an array of characters; in C++ you have a container that owns its characters. The functions you know from vector are mostly there - `size`, `empty`, `[]`, `at`, `push_back` - and a string has many more besides. {+ It is its own class, not `vector<char>`: the shared functions are a subset of vector's interface, and string adds things like `find` and `substr` that vector does not have. +}

So we have `size`, the function that tells you the size of the string - the number of characters in it. `empty` checks whether the string is empty. You can access the ith element of the string with the square bracket, and otherwise you can use the `at` function. If you access directly with the square bracket you can go out of bounds, because it does not check against the size of the string; if you use `at` and it goes out of bounds, it gives you an error.

Then there is a function called `substr` - "str" is short for string, so it is "substring". What is a substring? If you have the string `abcd`, then `bc` is a substring of `abcd`, because it is contained inside it. It is like a subset, but not exactly: in a subset you can take any elements in any order, whereas in a substring you have to take a contiguous run of elements inside the string.

[A student asks how to change one character.] You use `at(1)` and assign some other character to it - that's it. It is the same as changing the value of an element inside an array; the same thing you can do in a string.

What does the `empty` function do? It tells you whether the string is empty. If a string is empty, what is in it? [Students guess: a sentinel character, a trash value, a garbage value.] Nothing - {+ `empty()` is true exactly when `size()` is 0. An empty string is perfectly well defined: it simply holds no characters, and there is no garbage in it. +} Here it checks whether the line is empty: `empty` returns true if the string is empty and false if it is non-empty. If it returns true, there is no text inside the line we are reading, and then it finishes; otherwise it goes through and counts the digits.

And instead of the square bracket we used on the previous slide, we can use `.at()`: the `at` function automatically checks whether the index is inside the string.

[A student says the index stays in range because the for loop controls it.] Yes, but suppose you accidentally make a mistake. This is a very simple function - ten lines of code - which you can read and check. But if it is a very big function, where you started a for loop a hundred lines earlier and then somewhere inside the loop you change the size of the line - you removed something from it - and you are still using the square bracket to access the index, then that index may now be past the end, which is undefined behaviour. We don't want that. That is why you use `at`: it throws an out-of-range error, `std::out_of_range`, as soon as the index is not less than `size()`. {+ Only the index matters: if the string grows instead, every old index is still valid and `at` does not throw; and an out-of-range `[]` is not a predictable garbage read, it is undefined. +}

[A student asks whether `at` always replaces the square bracket.] Only for a vector-like type. If it is a C-style array you cannot: if you declare `int a[5]` you cannot use `at`; if you use `std::vector<int>`, then you can.

## 12. getline reads a complete line, including spaces
Status: taught

Let's start with taking a string as input. This code has the basic `iostream` and `string` headers; we declare `word` as a variable of type string and take input into it. Now, if I type "IIT Indore", what will it print? It printed "IIT". Why did it not print "Indore"? [A student: The space.]

The space becomes the delimiter - it is called a delimiter in the sense that it breaks things up. So here the string is broken at the space. There are two delimiters: one is the space, the other is the newline. The newline is the universal delimiter: it breaks everything. A space breaks the input for a string - and it is also a delimiter for, say, an integer.

[A student asks what else can be a delimiter.] Tabs, and so on. You can specify your own delimiter by using the version of the function that takes one - you can say a comma is my delimiter. If you are reading a comma-separated value file, a CSV file, the values are separated by commas, so you specify that a comma is your delimiter, and then it reads a new value every time it meets a comma.

So whenever you read a word and you put a space in the input, the reading stops at the space: it will not continue reading after the space.

What can we do then? Instead of that, if I write `getline`, you can see that it gets the entire line. When we use this function `getline`, it takes the entire string until the line ends - and the line ends at the newline character, which is what you get when you press Enter on your keyboard. That is where `getline` stops: it reads and reads, and stops when the newline character comes. So you can put spaces or anything else and it will take all of it as input.

[Mixing `cin` and `getline`.] Let's modify this code. If I run it and enter a number and then some text, what happened - why do you think the number was not printed? I am printing `n` here: this `cin` reads the number, and then `getline` reads the rest of the line, and then we print the line - and the line does not contain the number, because the number was already read by `cin`.

But this `cout` is not working - that is what is happening. Now, what did I do? I added the newline character when printing with `cout`. {+ The output side is the simple part of this story: without a `\n`, the next thing printed just continues on the same terminal line, so the number and the line run together; printing never touches `n`. +}

How does the terminal read your input? Whatever you type, it reads - but there is a delimiter. When you are reading an integer, what is the delimiter? A space. So it stopped at the space. Then we used `getline` to read from the same line, and because there was no newline character yet, it read the space and the word I wrote after it - so both the space and the word went into `getline`.

Think of the input as a string buffer: whatever you type on the terminal is in it character by character. `cin >> n` takes the digits and stops at the delimiter, and the rest of the line is still sitting in that buffer for whoever reads next. When I output `\n` in the `cout`, the terminal starts a new line, and the whole line is printed on that new line.

[A student asks what happened to `n`.] [A student: but `n` and `line` are separate variables.] Yes. {+ They are separate objects, and printing one cannot overwrite the other. What looked like the number disappearing was two outputs landing on the same terminal line, together with the leftover input being read into `line`. +}

[Looking again.] Ah - then you are reading with `cin` from the leftover buffer. The input is also a buffer. What does the input contain? 2, space, the word, Enter. `n` already read the 2; then the space and the word are inside `line`. [This is the right account: `cin >> n` leaves the rest of the line in the input stream for `getline`.] If I print a space, that is again a delimiting thing, so it prints; if I don't print anything - oh, now it is printing.

What I would encourage you to do is always put a delimiter after you output something - an `endl`, or a space, or something like that. That is the standard practice: whenever you print something, there should be a delimiting character after it, either a newline or a space. Don't forget to use the delimiting character. The logic I explained about the buffer is still valid {+ - the input buffer: `cin >> n` leaves the rest of the line, including the newline, in the stream, and the next `getline` reads exactly that, often an empty line if you pressed Enter right after the number. +}

So why do you think it is printing two spaces here? After you enter the number, that space is still read into the line, because `getline` reads everything up to the newline character. I am printing only one space, so the other one came from the input.

Two things to remember: the delimiting characters when you print something; and that `getline` reads up to the delimiting character, which is then consumed by `getline`.

[A student asks whether a string can be divided at a newline.] You can define your own function that divides the string into two parts and puts a newline character in it; we can check that. ## 14. Positions and lengths make text operations explicit
Status: taught

Then there is the `find` function. What does `find` do? It finds a particular substring inside a string. How would you write the code for `find` yourself? You write a for loop that goes through the string one character at a time; whenever something matches, you store a boolean - if it is true you output true, if it is false you output false - and when it is true you also have to find the exact position where the substring is.

Then we can take input into the string by using `cin` and also `getline`. I will tell you what the difference between `cin` and `getline` is.

[A student asks whether `find` returns true or false.] `find` returns the position if the substring is found - the index of the start of the substring. [And if there are several?] We will see what happens if there are several.

The `find` function finds a particular character inside the string. Here it finds this character - what is this minus sign called? [A student: partition.] Anyone? [A student: Hyphen.] Yes, this character is called a hyphen, also called a dash. So `line.find` returns the position of the dash, and then we check whether that is a valid position in the string. `npos` means "not a position", so if the result equals `npos`, the dash does not exist inside the string, and then it tells you there is no delimiter. So you can use the dash as a delimiter as well - you can define your own custom delimiter: comma, dash, at sign, space, newline, tab.

If there is a dash, then I take the substring up to the dash: I start the substring at 0 and go until the position of the dash - so I am splitting the string. Let's see: I enter "ABCD" with no dash, and it tells me there is no delimiter - there was no dash. But if I enter "ABC-" and something, it splits the string into two parts: one before the dash and one after.

How is it doing it? With the `substr` function. The substring starts at 0 and ends at the dash, where "dash" is the position of the dash inside the string. Let's print it: the dash is 3, which means the index of the dash character is 3, because it is in the fourth position. So always remember - and I am telling you this again and again, every lecture - the index starts at 0.

So we take the substring starting from 0 and ending at the dash, which is "ABC" - everything before the dash. And then we take the second substring, which starts at index dash+1 and goes to the end. Whenever you don't specify the second argument, it goes until the end of the string; if you specify the second argument, it takes that many characters.

For example, if I write 4 here: what did it do? It printed up to index 4 - but is it really index 4? Let me start this one at 1 instead. It started at index 1. And if I start at 3, it starts at index 3, which is D, and prints length 4: "D-WE", four characters. So the second parameter of `substr` is the length of the substring, not the position: the first is the position, the second is the length. Remember this.

So if I write "dash" as the second argument when I did not start at zero, it doesn't work correctly. When the starting index was 0, I could use the index of the dash as the length, because the length from 0 up to the dash is the same number. But if I start at a non-zero value, I have to write "dash minus 3" if I start at 3 - the dash is at 7, so 7 minus 3 is 4 - and then it prints from index 3 up to the dash. If I don't subtract, it would take length 7, which I don't want.

[On a failed search.] So `find` reports failure. Another thing: if I print this value, what is it? Do you remember? Can you recognise this number? [A student: Max int minus 1.] It is `npos`: `std::string::npos` is `size_type(-1)`, all bits one, so printed as an unsigned value it is the largest `size_t`. {+ On these 64-bit lab machines `size_t` is 8 bytes, so the number is 2^64 - 1, a 20-digit number. Never hard-code it: compare the result of `find` against `std::string::npos`. +}

## 16. Character classification requires a safe unsigned-char conversion
Status: taught

[Running the `cin` plus `getline` program once more.] What the program is doing is storing the number in `n`, and then, because `cin` stops when it stops meeting digits - `cin` reads character by character, and as soon as a character is not a digit it stops - we print the number and then the line. This space here is the one I print, and the line itself does not contain any other space, so it starts at A; if I had put a space in the input, that space would be from here.

Now, for example, we want to count how many digits are in a string. How do we do that? We define `digits = 0`: every time you are counting something you start with the initialisation. Then we iterate through the size of the string - and we don't know the size of the string, because we are getting it from the user with `getline`; the user can input anything.

Then we write `static_cast<unsigned char>` of `line[i]`, where `line[i]` is the ith element of the line. Is that true - is `line[i]` the ith element? No, it is the (i+1)th, because the index starts at 0. So we take a copy of that particular element as an `unsigned char`, and then we can use this function called `isdigit`, which is already built in. `isdigit` tells you whether the character is a digit or not, so it counts how many digits there are.

[Running it.] If I input something, it tells you there are 10 digits in the string. And I can also do it with "abc123": it is just counting the number of digits.

So how is it counting the number of digits? It takes the string character by character; every character it converts to an unsigned character type; that becomes the input to the `isdigit` function. To do the type conversion we use `static_cast`, and `isdigit` comes from `<cctype>` - the C character-type header. So you convert a copy of the character to `unsigned char` and pass that to `isdigit`. {+ `static_cast` is part of the language and needs no header, and `unsigned char` is a built-in type; the only thing `<cctype>` gives us here is `isdigit`. The string itself is untouched - `isdigit` only looks at the converted copy. +}

{+ The conversion is not optional: always write `std::isdigit(static_cast<unsigned char>(ch))`. On a machine where plain `char` is signed, any character with the top bit set becomes a negative value, and passing a negative value to `isdigit` is undefined behaviour, not just a warning. Ordinary characters such as a backslash or a quote are fine either way. +}

[A student asks what an unsigned character is, and why a character should have a sign at all.] {+ It is the same one byte as a plain `char`, read as 0 to 255 instead of -128 to 127; it saves no memory. The reason for the cast is to make sure the classification functions see a value in 0 to 255 rather than a negative one. +}

Another thing to notice here is that we don't need to know the size of the string that is being read from the user.

[A student asks whether using `int i = 0` instead of `size_t` in the for loop gives an error.] It is fine. The size type is an unsigned integer type. {+ `std::size_t` is the type `size()` returns - 8 bytes on the lab machines, wider than `int`, not narrower - so using it for the loop index means the comparison does not mix signed and unsigned. +} And if a character value were somehow negative, the behaviour would be undefined, which is why we use an unsigned character: we don't want the sign bit to influence the value of the character.

## 21. C-style strings end at a null character and need manual bounds care
Status: taught

This is the last thing. In the C style, when you store a string, it stores this `\0`. The `\0` is the special character in a C-style string that tells you which is the last element of the string.

Here it can store a string of size 4, but the character array could be of length 100, because you don't know the length in advance. If I am taking your names as input, everyone has a different length of name, so I would take, say, `char c[100]` - but `c[100]` will not be filled completely, and I want to tell the program where the string ends. The string ends at `\0`; that is the use of `\0`.

But don't use C-style strings - use the C++ standard string all the time. C-style strings have a lot of these issues with `\0` and with buffer overflow: the array does not know its own length, and nothing checks the destination when you copy into it. {+ The `cin` then `getline` surprise from earlier is a different matter: that is the leftover newline in the input stream, and it happens exactly the same with `std::string`. +} If you use C-style things, those problems are worse. So don't use C-style strings; only use C++ style strings.
