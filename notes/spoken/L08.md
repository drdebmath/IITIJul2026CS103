## 1. References, overloading, decomposition, and the call stack
Status: taught

If you are calling a function on some variable, and you want that variable itself to change - to take different values, different positions - how can you do it? That is where something called an alias comes in. How many of you know what the word "alias" means? Have you seen the TV series *Alias*? That is probably before your time.

An alias is like a spy who goes by a different name, but is the same person. You become James Bond: James Bond is not a real name, it is an alias. And another alias of James Bond is - [a student: Agent 007.] That is an alias. That is what we do for variables: you give them aliases, and through those aliases you can change the values of those variables.

That is what we will learn today: how to send a variable to a function as an alias, so that the function can change the value of the variable that was declared in `main`, or wherever the function was called from - because the variables declared inside a function are local to the function, since the scope of a variable is its curly braces. We have learned that. And then, towards the end, we will see something about recursion.

Every time we send a copy of the variable, it is called pass by value: you copy the value of the variable and send that value to the function. When we send a reference to the variable - an alias - technically we say pass by reference. Those are the technical terms: pass by value and pass by reference. "Copy", "alias", "James Bond" are not the real technical terms; if you read a textbook you would not find these.

## 2. Parameter roles are visible at the interface. · Return two results without global state
Status: taught

Let us look at this piece of code, `orderPair`. What does it do? It takes four values - there are four parameters. What are they? The first two are `first` and `second`; the second two start with this symbol, the ampersand - the "and" that you write in English. When you write an ampersand after the variable type, that becomes pass by reference, which means we are creating an alias of the variable.

What is this function doing? It is only four lines. [A student: It is comparing the first and the second, and storing the smaller one in `smaller`.] Yes - it checks which of `first` and `second` is smaller and which is larger, and stores the smaller value in `smaller` and the larger value in `larger`.

But `smaller` and `larger` are passed by reference. Here the function is called, and it takes four arguments: the first two are integers, and we just give two numbers directly instead of defining variables.

[A student asks about `int&`.] Alias means that instead of passing the value of the variable, you send the variable itself: the parameter becomes another name for the caller's variable, so reading or writing `smaller` reads or writes `low`. {+ Underneath, the compiler usually implements this by keeping the address of `low`, but you never see that address and never convert anything - `int& smaller` simply is `low` under another name. Pointers, which do hold addresses you can work with, come later in the course. +} So whatever you change in `smaller` or `larger`, those and `low` and `high` are the same thing. `low` is the variable we declared here, and we are sending it as `int& smaller`, so `smaller` is another name for `low` - that is what an alias means.

Now `smaller` and `low` are the same thing, so you can assign to it. If they were different things, you could not: the assignment operator works between two things of the same type. {+ With plain values the compiler can convert for you - assign an `int` to a `double` variable and the value is converted into a new `double`. A reference is different: there is no value to convert, only a name for an existing object. So `double& smaller` cannot bind to `low`, which is an `int`, and the code does not compile. A conversion would have to make a separate `double` object, and writing to that could not change `low`. +} So the reference has to have the same type as the variable it names.

So I call `orderPair` with two values directly, because a copy of the value is what goes in for the first two parameters - I don't need variables for those. But I want the output of this function in these variables, which is why I am passing `low` and `high` by reference. I am passing the variables `low` and `high` - not their values - as references. Whatever `smaller` and `larger` become inside the function is reflected in `low` and `high`.

So let us see what it does. [Running the program.] It prints 4 and 17. But what are we printing here? We are printing the variables `low` and `high`, and `low` and `high` were initially 0 and 0. So if we don't pass by reference - suppose I remove this ampersand - what will happen? 0 and 0, because the values would not change: whatever modification happened would stay inside the function. If we want the modification inside the function to be visible outside, we have to pass the variables by reference.

[A student asks whether we have eliminated the return.] No, that is a different thing. We did not eliminate the return statement; what we did is capture the modifications made inside the function in variables outside it. But this is one of the ways you can avoid a return - because how do you return two values? When you write the return statement, it is over: `return` hands back a single object, so you cannot return two separate values. {+ The one object you return can be a compound value - a `struct` or a `std::pair`, which we will learn later - but with the types you know now, writing through reference parameters is the way to get two results out, and that is what `orderPair` does here. +}

So, if we wanted to do it with a return statement instead, you could return a boolean - true if the first is greater than the second, false otherwise - and then, back in `main`, you check the boolean and print low, high or high, low accordingly.

But here we are not even storing the input values in variables: we are putting 17 and 4 in directly. If you do that, you cannot ask the user for the input again, unless you store it in a variable. That is the point of this exercise.

## 3. The general form of the three parameter modes and an overload set
Status: taught

So today we will see the ways in which we can declare functions. First you specify the return type, and the return type can be `void`. Then the function name. Then the data type for each parameter and the parameter variables. And when you put `const` on it - why would you want `const`? What do we use `const` for? We don't want modifications. That is why you put `const`: then, if you accidentally modify this variable somewhere inside the function while typing code, the compiler will tell you that you modified a constant value and it is an error.

Then this is how you pass a default value to a parameter. What do we mean by a default value? Sometimes your function has a lot of parameters and you are not changing the value of all of them, so you want to set a default value for a particular parameter.

And, on the other side of aliases for variables, there is overloading. How many of you have the same name as someone else in this class? You can have the same name for several people - and similarly you can have the same name for several functions. If you have a different set of inputs for the same function name, those functions are called overloaded functions. Overloading means the same function name with a different set of parameters. ## 7. Overloads share a name only when parameter lists distinguish them
Status: taught

When I was talking about overloading: overloading means one function name that is repeated. Here both functions have the same name, `absolute`. One takes an integer input and the other takes a double. The compiler then selects which function you mean: if you call `absolute` with a double argument, it selects the double version; if you call it with an integer, it selects the integer version. {+ This choice is made by the compiler, when it compiles the call: it looks at the types of the arguments you wrote at the call site and picks the best match. Nothing is chosen while the program is running. +}

But if you write the same function with only a different return type, that does not create an overload. It is only an overload if the parameters are different - different data types, or a different number of inputs. If only the return value is different, that is not an overload.

[A student asks what error you get.] {+ Two functions with the same name and the same parameter list, differing only in return type, are not accepted: the compiler rejects the second declaration, so the program does not compile at all. +} An error also comes if, say, the function takes two inputs and you send three. The case where no error comes is different: if there is one function taking two integers and another taking two doubles, and you meant to call the double one but called it with integers, it will call whatever matches best with the way you called it. So if you accidentally call the wrong function, the responsibility lies with the coder - the compiler is automatically selecting what it considers the best match.

[A student asks why not just give the functions different names.] You need overloading because you don't want to remember different function names for the same idea. Suppose you are computing the absolute value of a number - the mod. Does it matter what data type the number is? No. But if you accidentally call the integer version instead of the double version, you lose the input's precision: if your input is 5.63 and you take the mod, instead of 5.63 you get 5.

Now you can define the absolute function for all the data types that allow it: one for integer, one for unsigned integer, one for double, one for float - as many as you want. All of them do the same thing, and the compiler chooses which one, so you get the output without changing the data type.

If you wanted to write only one absolute function, what would you have to do? Your input is sometimes an integer and sometimes a double, so every time you would have to write a bigger piece of code checking the data type: if it is this type call `absoluteInt`, if it is that type call `absoluteDouble`. Then you have to define different functions anyway and remember all those names - and you might have a thousand functions in your code base. Do you want to remember a thousand function names? No. You want to remember things that are easy to remember. That is why function overloading exists: you write one function, and then you repeat the same function name with different parameter data types, and because it is defined for each data type it will not misbehave with your input.

So the H pair is not a legal overload because - [students: the input types are the same.] If only the return type is different, it is not a legal overload. An overload works only when the input types are different, or the number of inputs is different. So, for example, the G pair is a valid overload.

For example, you want to write an `add` function that takes 2 inputs, 3 inputs, 4 inputs. You can define `add` for 2 inputs, for 3 inputs, for 4 inputs: with 2 inputs it is `a + b`; with 3 inputs it is `a + b + c`. That is how you would do it, because you are adding numbers anyway, and the only question is how many you are adding this time.

## 11. Each active call owns a stack frame until it returns
Status: taught

How do functions work? Functions work with something called a stack frame. The frame contains the definition of the function, the types of the variables it has, and the values of each of those variables. So the frame itself is different for each call.

Every time a function is called, a new frame is created. You call the function with different values, and another frame is created; when the frame is created it takes the values you are sending to the function. Every time you call the function, a frame is set up for that call, and in that frame you assign the variables inside the function. {+ Overloaded functions fit into this picture very simply: the two `absolute` functions are two distinct functions, and the compiler has already decided which one a call refers to before the program runs. Each call of whichever one was chosen - and each call of any function, recursive or not - gets its own frame holding that call's parameters and locals. +}

When you declare a variable, what happens? The compiler allocates memory somewhere in the RAM and assigns the value to the variable. Something similar happens when you call a function: {+ the function definition is the template, compiled once, +} and when you call it a frame is created for that call, and in that frame all the variable values are written; when the call returns, the frame is removed. That is what we mean by a stack frame. The stack itself is something we will learn later. {+ For now, all you need is that the frames are piled one on top of another: the most recent unfinished call sits on top and is the first to finish and be removed - last in, first out. +}

The answer is B. When I call a function, you have the frame of the function, and inside that call I am making another call, which gets its own frame. Think of it as a big bucket, and inside it you put a smaller bucket, and inside that another smaller bucket. Have you seen Russian dolls? You open one and there is another doll inside, and you open that and there is another one.

So when you are calling `factorial(3)`, `factorial(1)` returns first, because it is the smallest bucket inside. You put buckets inside buckets and you pour water: the smallest one fills first, then you remove it and pour water, and the second smallest fills, then you remove it and the final one fills, and then you get the filled bucket. Until the inner ones fill, you cannot fill the outer one. That is what happens whenever you call a function inside a function.

[A student asks which one is called first.] `factorial(3)` is called first, because it is called in `main`. Then, inside `factorial(3)`, `factorial(2)` is called, and inside `factorial(2)`, `factorial(1)` is called. Once `factorial(1)` returns, `factorial(2)` can be computed; once `factorial(2)` returns, `factorial(3)` can be computed; and then `factorial(3)` returns and we are back in `main`.

## 12. Recursion needs a base case and a smaller next call
Status: taught

You can call the same function inside itself, and that is something called recursion: we are defining a function in terms of itself.

The function here is `factorial`. How do you compute n factorial? You can write it in a for loop. But you don't always have to: you can write it as a function that calls itself. And how long does the function keep calling itself? Until it terminates. When does it terminate? When n equals 1. You can see on line 2: if n is less than or equal to 1, it returns 1. So if you call it for 0 factorial, the value is 1 - that is the base case; and 1 factorial is also 1, which is another base case.

Think of it as induction. When you do induction you have your base case, and then the induction hypothesis: if this is true, then that must be true. We are doing the same thing, but in the reverse order. We define the function assuming `factorial(n-1)` is already known: if you want to compute n factorial, you just multiply n by (n-1) factorial.

If I want to write the sum of the first n numbers, can I write it like this? What would I write? n plus the sum of n-1. And what is the base case? If n equals 0, return 0. That is the base case; and if you are called with n, you return n plus sum(n-1). That's it.

[A student asks whether recursion is an inefficient way to do it in this case.] Yes, it is. But it is a concept, and the concept is important; we are not talking about efficiency right now. If you know the range, a counted `for` loop is the efficient way. {+ If you do not know how many times to repeat, that is what a `while` loop with a stopping condition is for. Recursion is about the shape of the problem rather than the range: you use it when the problem is naturally defined in terms of a smaller instance of itself, with a base case you can reach +} - and for those problems recursion is easier to write. If you had to write this factorial in a for loop, how much would you write? Four or five lines. Here you are writing two or three lines. Which is easier? Writing the recursion is easier, because you only need to define the function and then call the same function inside itself.
