## 6. Signedness and width determine the numeric range
Status: taught

Now a task for you: can you tell me the maximum value you can store in an integer? [A student: 2^32 - 1.] Why? Because it uses 32 bits.

What if you have to store negative numbers? [A student: One sign bit and 31 bits.] Then what is the maximum value with one sign bit and 31 bits? 2^31 - 1, because the first bit tells you the sign.

You can also take a smaller integer. Take a 1-byte type as the example. How many bits are in a byte? 8. If it is 8 bits and the first bit is reserved for the sign, plus or minus, then the remaining 7 bits - what is the boundary value? 2^7 - 1. {+ The 1-byte signed type is `signed char`, also called `int8_t`, with range -128 to 127. A `short` is at least 16 bits, 2 bytes on the lab machines, so the same reasoning gives it a range of -32768 to 32767. +}

When you say you are storing something in an integer, what do you mean? It means the variable stores the value. When you define a variable with the keyword - `int` is the keyword - and then write a variable name and then equals something, that value is stored in this variable, and when the program later refers to this variable, it can get the value back. We will learn how this works when we learn about pointers, in lecture 6 or 7.

Similarly, a boolean carries one bit of information: you can have 0 or 1; you cannot have more than that. {+ A `bool` variable still occupies a whole byte in memory, as we measure with `sizeof` later. +}

There is short, and there is also long. And then there is `char`, which stands for character.

Every time we store a value we need to give that value some meaning, and how do we decide which meaning? It depends on the range and the precision of that value. For example, if you want to store your roll number, what do you need? [A student: Integer.] Is an integer good enough? Can your roll number be negative? No. So you can use an unsigned integer, because an unsigned integer does not take negative values.

Every time you store a value, look at the range. The range of your roll number starts from 2-6-something and goes to 2-6-something. So do you really need to store your roll number as an integer that goes up to 2^32? No. What can you do? The other way to store your roll number is as a string, or as a concatenation of several strings. What is concatenation? Joining.

I already told you about signed and unsigned. Adding a sign to a variable fixes the first bit of the variable to be a sign bit: if it is 0 the value is positive, and if it is 1 it is negative - or the other way round; I don't remember.

What will happen if you make an `unsigned int` and set the value to -1? It is impossible, so the compiler will convert the value to the unsigned one. How do you think the unsigned numbers represent negative numbers? In a signed number the first bit is the sign; in an unsigned number it loops around. You go from 0 up to the top of the range, and then -1 starts from the top and goes backwards: -1 becomes the largest value, -2 the next one down, -3 the next. That is how the unsigned int wraps around. {+ The top of the range is 2^n - 1 for an n-bit type: for an 8-bit unsigned type -1 becomes 255, -2 becomes 254, -3 becomes 253, and for a 32-bit `unsigned int` -1 becomes 2^32 - 1, which is 4294967295. +}

Basically, you know modular arithmetic - you know groups? Maybe not groups. ## 8. Four objects, four boxes — habit picks the wrong one
Status: taught

Everything goes into the compiler, which is this blue box. But everything has a different meaning, and the compiler wants to separate them into their own boxes. You don't want everything to be of the same type - variables should have the types that fit them. Based on the meaning, you have to choose the container, not the other way around. This is very important, and it is the first takeaway of programming: you choose the variable's data type based on what you want it to do.

Not "I have chosen `int`, it looks fine, I will use `int`", or "I will make everything double because double holds everything - integers, decimals, fractions". That is not how it works. Based on what operations you want the variable to perform, you choose its type.

## 12. "It is a number" is not a finished type decision
Status: taught

Then, for example, you want to store the CGPA. You want a float - or what else can you do? Every fraction can be represented as two numbers divided by each other, so you can store two integers separately and say that the fraction is a divided by b. And a divided by b is very precise compared to a fraction stored as a double. If you store 1/3 in a computer as a double, it would be 0.3333333, precise up to some number of digits, and after that you don't know. Because there are fractional numbers whose expansion never ends, if you store them as a double you are losing precision. If you store 1/3 and multiply it by 3, do you get back 1 in the computer? With a double it would be difficult to get back exactly 1. But if you store the fraction as 1 and 3, then when you multiply by 3 you will definitely get back 1. So where you need precision, and you know all your computations will be in terms of these numbers, you can choose two integers to store a fraction rather than a double.

## 13. Type choice follows meaning, range, and precision
Status: taught

You have some data, and you don't want that data to live in a variable without a type: we want a type associated with the data so that the compiler knows what to look for. If you say it is integer data, the compiler will look for integers; if it is fraction data, float or double, it will look for that; similarly for a character, a string or a boolean value.

The compiler will also allocate a proportional amount of memory to these variables. So there are two parts: when you write the type of the variable, you are not just assigning a value, you are also telling the compiler how much memory this variable needs. If I define a boolean variable, how much memory does it need? One bit. But sometimes the compiler cannot assign one bit, because the minimum block size in a computer is one byte or four bytes; so when the program is running, the variable occupies one byte. There is a difference between the allocation you write down and what actually runs. {+ Separate `bool` variables are not packed together: if you declare eight boolean variables, each one still takes its own byte, and `sizeof(bool)` is 1 for each. If you really want eight flags in one byte, you use a bit-field or `std::bitset<8>`. +}

How the compiler works when you declare variables is that it takes the address of some memory and assigns a name to that address. That is what declaring a variable means. You have a hostel room, so you have an address: you are in this hostel, room number something, unit number something. But that address by itself doesn't mean anything to me. If I say "whose room is it?" - [a student: Anshuman's room.] And where is your hostel? BA07. If I tell the computer BA07, it knows where BA07 is, but I don't; I want to know BA07 as Anshuman's room. That is the difference. When we declare variables we want a name associated with some value, at some memory the compiler chose.

How do you choose which type of variable to declare? From the type of data you want to keep. If you are keeping integer data you need an int; if you are keeping fractions you need a double; if you are keeping track of a flag you need a bool. The type choice follows from the meaning of the variable, its range and its precision.

And, as someone said last time, if we have the value of pi in our program we don't want it to change in the middle, so we put `const` before it. If you don't want to write the type initially, because you don't know how you are going to use it, you can use the `auto` keyword, and depending on the value you assign, `auto` will infer the type you need.
