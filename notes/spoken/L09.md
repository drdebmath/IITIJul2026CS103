## 5. An index is valid only inside the array’s bounds
Status: taught

The size is a constant that is already fixed at compile time: when you compile the program, the constant is assigned. The index always starts from 0. And in the for loop you should always be careful about the boundaries: if you go one step before or one step after the array, funny things can happen.

A C-style array you declare like this: `int`, the name of the array, then the size, and then it gets assigned like this.

What is the array, then? The name of the array is not an ordinary variable holding one value. When you use the name of a C-style array on its own, what you get is an address: {+ the array is a block of memory, and in most expressions its name converts to a pointer to its first element - that address is what gets printed when you write `std::cout << a`. +} The address points to some memory block, and the value at that memory block is what we are storing. So there is a hierarchy.

Suppose you meet a person and you ask what their name is. The name is what you identify them by, but the name is not everything; their values are something they have. For example, their roll number is different from your roll number. So suppose someone's value is their roll number. If I have an array called `students` and `students[5]` is someone, then 5 is their index number, and the value at that index is, say, their roll number - which is different from the index number. So do not confuse the name, the index and the value: these are three different things. The name is the name of the array; the index is the position within the array where your value is stored; and the value is the value you care about.

This is how you declare an array called `voltage`. The index is the position of the value in the array - the position of the memory block you are trying to access - and the last element of the array is at index n-1, where n is the size of the array.

## 8. Game evolution: Linked segments represent a growing body
Status: taught

Suppose you want to find one temperature that is bad: you run a for loop and put an `if` condition - if the temperature is greater than 40, that is bad.

Then, in the snake game for example, you can declare the arrays for rows and columns, and put the values in for the rows and the columns. And then you say: this is the next row, this is the next column, collision is false. The rows and columns are the positions of the snake's body. If the snake has length 4, I have 4 values for the 4 rows the snake occupies, and 4 values for the 4 columns, because each body part of the snake is in one row and one column - it is a pair of values.

So if I have rows and columns like this, I can work out whether the snake is colliding with itself by checking whether the next row and next column - which is the head of the snake - match any body part of the snake. If the next row and next column are part of the snake's body, we say the snake has collided with itself, and it is game over.

That is how you can store the snake's body in two arrays: one array stores the row numbers, one stores the column numbers, and the same index in both gives you one body part.

## 9. Range-for visits every element without manual indices
Status: taught

Here is what I meant by the enumerator. You can write the for loop like this: if you use `#include <array>` in C++, you don't need to specify the lower bound, the upper bound, the `++`, the condition and all those things. What you write is `for (double value : voltage)`, where `voltage` is the name of the array - and the loop visits each element in order, from the first to the last. I have been calling this an enumerator; {+ the proper C++ name is a range-based for loop, and there is no index in it at all: `value` is each element of `voltage` in turn, not its position. If you need the position, write an indexed loop or keep a counter beside the range-for. +} So every time, this goes through the elements.

When you write a for loop with a standard array, you write `i = 0`, `i < length`, `i++`, and then you access the array as `voltage[0]`, `voltage[1]`, `voltage[2]`. Instead of that, here, inside the for loop, `value` itself becomes `voltage[0]`, `voltage[1]`, `voltage[2]` over the run of the loop. That is how this enumeration works. You can always use the standard form with an index and `i++`; the other way is to declare this value, colon, the array name, and then the value itself takes all the values of `voltage` in turn.

## 11. A std::array parameter carries its own size
Status: taught

Let us define this function called `mean` - mean means average. How do you compute the mean? What are we doing here? We are taking the `values` array passed by reference. We learned that in the last lecture: you can take the address of the variable instead of a copy of the variable, so you are taking an alias of it, and then through that alias you can access or modify things.

So here we are taking the `values` array by reference. If you remember, when we printed `&a` it printed something like this, and that is the address; and if I print just `a`, it still prints the same thing, because `a` on its own is not a value - what you get from the name of a C-style array is an address. `a[0]` is the value: that is the first element of the array. {+ To be precise: the array itself is a block of memory holding all the elements, and when you use its bare name - and always when you pass it to a function as `double values[]` - it converts to a pointer to its first element. That conversion is exactly why the length does not travel with a C-style array into a function: the function receives an address, nothing more, and you must pass the length beside it. `std::array<double, 5>` is different: it is a proper object whose length is part of its type, so `mean` can take it by reference and still ask `values.size()`. +}

So, for example, this is why the `values` array is described as a pointer. Whenever we are referring to an address, we say it is a pointer - because it is pointing at something: the address points to a memory block. That is why it is called a pointer.

You should remember this clearly and tell these apart. What is the difference between the address, the value, the index and the pointer? Those are four terms you have learned today. All of them are important and they will be used throughout the rest of the course, and you need to understand them properly.

## 12. Out-of-bounds access has no reliable result
Status: taught

[Demonstrating an uninitialised array.] If I don't initialise, and I declare the length of the array to be 5, what happens? It prints something - what are these random numbers? They are garbage values. Whenever the compiler allocates these 5 blocks of memory to the array, those memory locations already have something written in them, because computer memory is not always free: it is not always empty or initialised to 0. Other programs are running, your operating system is running. So when you access that memory, it may have been used previously by some other program which wrote something there, and what was written before is what you see. These are called garbage values: they are not assigned by your program, they come from somewhere else that already existed.

So what happens if I do this? Will it give me a compilation error? No, there is no compilation error. What happens is that you said your array runs from 0 to 4, and now you try to read a sixth element that does not exist. What you saw here is that it read whatever happened to be in the next memory block - garbage, or sometimes 0. {+ But do not take that as a rule. An index outside 0 to n-1 is undefined behaviour: the language promises nothing at all about what happens. On one run you may see a leftover value, on another zeros, on another a crash, and the compiler is even allowed to assume it never happens and rearrange your code on that basis. +} When your program tries to touch memory that the operating system has not given it, the operating system stops it, and that is a segmentation fault. {+ Modern operating systems keep each program in its own virtual memory, so you are not actually reading another program's data; you simply hit an address your program is not allowed to use. +}

[A student asks about accessing index 600.] It still lets you access these things - some are 0, and there is also a lot of garbage. [And whether it will crash:] the program is only given a certain amount of memory to run in, so eventually it will crash, because the amount of memory is fixed.

You don't only have to go out of bounds in one direction - you can also go negative. When you declare an array, the name of the array is the address of the memory block that the compiler gives you for the first element. When you index, you are accessing the next memory block: `a[0]` is that block, `a[1]` is the next one, `a[2]` the one after. And how long is a memory block? It is defined by the data type: an `int` is 4 bytes on these machines, so `a[5]` is 20 bytes after `a[0]`. {+ In general `a[k]` sits `k * sizeof(int)` bytes after `a[0]`; the 4 is what `sizeof(int)` measures on our machines, not a rule of the language, so write `sizeof` when you mean the offset. +}

Think of it as standing in a train: this is coach S7; you go one way and it is S6, and back, and the other way is S8. At some point the train only goes up to S10, and if you move further there is a virtual S11 which does not exist in the train - but something is there. If it were a ghost train, I would just go and sit in S11 with whatever other ghosts are there. Those are the garbage values.

[A student asks when it gives an error.] If that train is gone and there is another train, from another company, and you try to get in, you cannot. So when memory does not belong to your program and you try to access it, the operating system gives you an error. The operating system initially allocates a lot of memory to your program, and you may not use all of it; once you go past that, and you try to access memory that is not yours, then you get the error. {+ Inside your own allocation nothing stops you, which is exactly why out-of-bounds bugs so often go unnoticed. +}

[Demonstrating an assignment out of bounds.] If I say `a[i] = -4` with a negative `i`, what happens? Something happened and it is doing an infinite loop, and it should not. [A student: it starts from i = -5, and i = -5 doesn't exist.] Yes, that's fine, but it is also moving: I was expecting that at -1 it would still just print. It is behaving arbitrarily - so don't write code like this.

What is the problem here? `int i` is also allocated memory somewhere. When I print `&a`, what am I printing? The address of the array - written in hexadecimal, which is why it starts with `0x`. So when I set `i` to -1, on this machine `a[-1]` happened to land on the memory of `i`: writing -4 there changed `i` itself, and `i` kept changing, which is why it ran in an infinite loop. That is the point of the demo: writing outside the array touches memory that belongs to something else. {+ Which something else is not fixed - it depends on how this compiler laid out memory on this run. Another compiler might put `i` somewhere else, keep it in a register, or remove the loop entirely. Out-of-bounds access is undefined behaviour: what you see is an accident of the layout, and you cannot rely on it or reason from it. +} We will learn more about addresses in a later class, when we do pointers.

The array is bounded; if you want to go past the end, it is undefined. If you try to access `voltage[5]`, and `voltage` is of size five, that is already out of bounds, because `voltage` goes from 0 to 4. Instead of saying "somewhere inside the array", we always have to specify the index to access a particular element. And if you don't know the size of the array - if you have declared it as a `std::array` type of array - then you can get the size with the `size()` function.

[On the poll about calling `mean`.] The answer is that this will give you a compilation error: you are saying the array is of size five, but the actual array that has been declared is of size seven, so you are sending something of a different size. {+ The compiler can catch this only because `mean` takes a `std::array<double, 5>` and the length is part of that type - a `std::array<double, 7>` is simply a different type. Had `mean` taken a C-style parameter, `double values[]`, there would be no error at all: the argument converts to a pointer, the length is not carried with it, and reading past the end inside the function would just be undefined behaviour. +}

[A student asks whether two arrays with the same name and different sizes can be defined.] No. The name of the array is fixed. You can have the same name with different parameters for functions - in functions that is overloading - but an array name is like a variable name, and you cannot have the same variable name twice in the same scope. If you declare `int n`, you cannot also declare `double n`; it will give you a compilation error. {+ With `std::array` the size is part of the type, not the name - `std::array<double,5>` and `std::array<double,7>` are different types - but that does not help: one name still means one object in a scope, whatever its type. +}

[On the last poll:] It is undefined behaviour. Even if there is no compilation error, you cannot assign to something outside the range.
