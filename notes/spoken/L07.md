## 1. Declarations, definitions, parameters, and return values
Status: taught

We will learn about functions today. What are functions? You have all learned about functions in mathematics: y = f(x). So f is a function that operates on this variable x, and you get the output y. A function in C++ is something similar: you give some input, and the output is the return value. The difference between a mathematical function and a C++ function is that here the return type is specified; apart from that, you can think of a function in a program in the same way as a function in mathematics.

A function has several parts. One is the declaration of the function - that is, you declare how you are going to write the function. Then the definition of the function, which says what the parameters are and everything else. The parameter is the input to the function, and the return is the output of the function. {+ The parameter list may be empty, and the return type may be `void`, in which case the function hands nothing back to the caller. +}

## 3. The general form of a declaration, a definition, and a call
Status: taught

The first thing, when you declare a function, is to specify the return type. What do you want to get out of the function - is it an `int`, a `double`, a string, a character, a boolean? Or is it nothing, in which case it is `void`? Whatever it is, you specify the return type at the beginning.

After the return type, you give your function a name. Function names and variable names work the same way. We will learn about overloading in a future lecture, where the same name can be given to several things, but for today: don't give the same name to several things - that is a bad thing to do, unless you have your own namespace.

So first you specify the return type, then the name of the function, and then the input of the function: one or more variables, which are the parameters of the function. The parameter type is the data type of the variable, and the parameter name is the name of the variable.

If you end it with a semicolon instead of curly braces, then this is called the prototype, or declaration, of the function: you are saying that you will write a function like this later. You are not defining the function; you are just telling the compiler that a function like this exists somewhere below in the file - because the compiler reads the file from top to bottom. First you declare the function, so the compiler knows this function exists somewhere in the file. If you declare the function and do not define it later, that is an error, so don't do that.

So first you declare the function, and then you define it. What is the definition? You again specify the same things - the return type, the name, the input - and then in curly braces you write whatever you want the function to do. That is the body of the function, between the two curly braces, and the body must contain a return statement {+ whenever the return type is not `void`: a function that promises an `int` or a `double` has to return a value on every path, otherwise running off the end is undefined behaviour and the compiler will usually warn you. A `void` function needs no `return` at all, and `main` may simply fall off the end, which counts as `return 0` +}.

Then, when you want to call the function, you call it directly by its name. You don't specify the return type when you are calling it; you are invoking the function inside your code, so you just call it with the arguments. And you don't specify the types of the arguments either.

And this is something called a lambda function, where the return type is inferred automatically - that is why there is the `auto` keyword, and then you give the name. Then square brackets, then the parameters, and then the return expression. This is for declaring a function that you need only at that particular place, inside that particular scope, and not everywhere. So if you want a small function that, say, adds one to a variable, instead of declaring it properly with a full definition and parameters, you just declare it directly as a lambda and you are done. We will see several examples of each of these.

The return type is the type the function returns to the place where it was called. The signature of the function is the name of the function and its inputs. The declaration just says that such a function exists somewhere below; the compiler has to look for it. The definition is where you say exactly what it does. And the arguments are what you pass to the parameters.

[A student asks whether you can call the function between the declaration and the definition.] Yes - that is the point of the declaration. You declare it first, before you define it, and then you can call the function: because you have declared it, the compiler knows the function exists and will look for it somewhere in the file. So you can now put the definition anywhere in the file, not necessarily at the beginning. If you do not declare it, then you must define the function before you call it. If you have declared it, you don't need to.

## 4. One function performs one explainable operation
Status: taught

Why do we need functions in the first place? Each function has one clear responsibility: the point of a function is to be responsible for computing something specific. When you write a C++ program you start with the `main` function, and `main` has the responsibility of being the first thing called {+ - by the runtime, once the compiler has finished building the program +}. Similarly, every function you declare should have its own responsibility, and that responsibility translates directly into what inputs it takes - the parameters - and what output it gives - the return value.

What does a function's specification state? It states the parameters - the inputs to the function and their types. If a function takes two integers, it should say: function name, `int a`, `int b`. Then a precondition that the caller must satisfy: any requirement the operation needs. For example, if you are doing an operation that is only allowed on a boolean and you pass a name, there is a mismatch. And then its return value - what the function gives back to the caller{+ , when its return type is not `void` +}.

You should also always write test cases for functions, and always give descriptive names, so that you know exactly what the function does. Don't write "my function is f(x)" - nobody knows what f(x) is. Say what the function does: if it computes the square of a number, call it `computeSquare`. In maths you write f(x) = x², but in programming, if you do that, you forget what f(x) was, and someone else's f(x) is x³, and then there is confusion.

How is a parameter related to a function? [A student: Parameters are the input to the function.] Right - the parameter is the input to the function, in the declaration or the definition. When you call the function, the values you pass are called arguments. {+ The two words name two different roles: the parameter is the named input in the declaration or definition, and the argument is the value supplied at the call, which is copied into that parameter. +}

[A student asks whether a variable defined outside a function can be used inside it.] Yes{+ - a function can read a global name directly, without declaring it again inside the function +}. But it is better to give it as a parameter{+ , so that the contract is explicit and the function does not depend on outer state +}.

[A student: When we define a function we define a parameter; when we call the function we give the argument.] Yes - the parameter is the generic thing, and the argument could be different variables each time. So: you have `int x`, `int y`, `int z`, and you can call `computeSquare(x)`, `computeSquare(y)`, `computeSquare(z)`. So x, y and z can all be arguments to the function `computeSquare`, but `computeSquare` is a function that takes one integer parameter as input. The parameter defines the input variable's type and the variable itself; the argument can be any variable of that type that you have defined where you are calling the function.

## 8. Value parameters isolate small inputs as local copies
Status: taught

Many of you answered 10. Why? [A student explains: we call the `doubled` function with x, whose value is 5, and inside the function it does `value *= 2`, and then it returns `value`.]

But the value that is returned is not stored anywhere: it is computed inside the function and then it is gone. When you print `x` afterwards, `x` is the same as before, because `x` was just the argument to the function. When you send an argument to a function, the function takes a copy of that variable's value; it does not take the variable itself.

So it takes a copy of x, whose value is 5, doubles it to 10 - but where is the 10? It is returned, and the return value is not captured in `main`, so it is gone. The value of x is still 5.

[A student asks about capturing it.] The function is called and it returns, but to store the return value you have to put an equals sign. There is no error if you don't - it is allowed; the value is just discarded.

So that is the takeaway: changing the value inside the function does not change the argument. Everyone made the assumption that the value of x would change, but x stays the same. What changed is the copy of x that went inside the function, and when the function returned that copy, we did not capture it - we let it vanish.

If the boolean is true - and here `dirtHere` is itself the boolean, so the condition in the parentheses is a boolean - then the immediately following statement is executed. If you don't write curly braces after the `if`, only the statement up to the next semicolon is executed.

You can see that we are putting `scoreAfterClean` inside the `cout`. That means it will print the score, because the return value is captured by `cout`: we are printing the function, and by printing the function what we print is the return value of the function - not the definition or the declaration of the function, but its return value. So whenever the score function is called, that output is printed.

But here the score is not stored. The score is 0, and when this function is called with the score and `true`, it will print 10. So you can see that the score here and the score there are not the same: this one is the parameter of the function, and that one is the variable declared inside `main`. The score in `main` is the argument to the function; a copy of its value goes inside the function, `dirtHere` is set to true, and it returns the new score - but the return value is not captured again. So the score in `main` is still 0: the copy that went inside the function became 10, and when it returned, it printed 10.

So it prints 10 because the first one is returning the value, and the second one is the variable you declared inside `main`. If you want to update the score, you have to write `score = scoreAfterClean(...)` - that is how you capture the output of the function. Then I just need to print the score, and it will print 10, because the score itself has changed.

## 12. A lambda packages short callable behavior where it is used
Status: taught

This is called a lambda function. What we did here is define something called `isPositive`. What you notice is that the lambda function itself does not have a name: instead of declaring a named function and calling it, you store the lambda in a variable directly. `isPositive` is the variable{+ , and what it holds is the lambda itself, not its output: you get a `bool` only when you call it, as `isPositive(3)` +}.

Instead of specifying the name of the function we just put square brackets, and then this is the input to the function, the value, and it says "return value greater than zero", which is a boolean. And instead of specifying the return type of the function, we capture it directly with the `auto` keyword, which automatically infers the return type, so you don't need to specify it.

I would ask all of you not to use lambda functions [for now]. The application is typically when you write big programs and you want to put small checks in between: you check the boundary cases with lambda functions. For example, if you are dividing by something you always want to check whether it is non-zero, so you define a lambda - `nonZero`, taking an `int value`, returning `value != 0` - and then you only have to check a boolean in the condition instead of writing the comparison there. {+ The comparison still happens, inside the lambda, so this saves no work; what you gain is clarity - the test has a name - and later these small predicates are what the standard algorithms take. +}

[A student asks about the square brackets.] The square brackets are part of the syntax; the empty `[]` is what you write here. {+ They are the capture list: empty `[]` means the lambda takes nothing from around it, and a non-empty one like `[x]` or `[&]` is still a lambda - it also takes hold of the surrounding variables it names. +}
